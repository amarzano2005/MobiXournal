# The hostile corpus

One `.mobix` per threat in the limits table of [mobix-format.md](../../../../../../../docs/mobix-format.md),
plus the smallest legal document. Generated by
`scripts/make-mobix-hostile-corpus.py` (deterministic: fixed timestamps, no clock or locale) and
driven by `MobixHostileCorpusTest`, which asserts each file's own refusal rule, a bounded refusal
time and a bounded heap, and that `00-smallest.mobix` still opens.

| File | What it is |
|------|------------|
| `00-smallest.mobix` | the legal neighbour: a manifest, a canvas and one page, correct digests |
| `01-too-many-entries.mobix` | 20 001 empty entries, one past the entry cap |
| `02-deflate-bomb.mobix` | 16 MiB of zeros deflated into one ~1000:1 entry |
| `03-deep-nesting.mobix` | a page nested 200 arrays deep, past the JSON depth cap |
| `04-duplicate-entry.mobix` | the same page name stored twice |
| `05-traversal-entry.mobix` | an entry named `../escape.json` |
| `06-wrong-digest.mobix` | a page whose recorded SHA-256 is not its bytes |
| `07-encrypted-entry.mobix` | a page entry with the ZIP encrypted flag set |
| `08-truncated-directory.mobix` | a file cut where its central directory begins — the file-backed reader refuses it; a streaming reader never consults the directory, so it still finds the intact entries |

Every file is small on purpose: the bomb stores a few kB, and the many-entry archive carries empty
entries, so the corpus stays reviewable as a diff.
