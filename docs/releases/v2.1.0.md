# MobiXournal v2.1.0 (Android) & Desktop v1.1.0 (Windows 11)

Released 2026-11-09 · 24 changes: 3 features, 6 fixes, 15 refactors — and one thing neither shell had before.

Both shells now **tell you when a newer build exists**. It is the release's headline, because it is the
first one this project has shipped that can hand you the next one.

## ✨ The update check, in both shells

- **At launch, once per process, silently.** Each shell reads the project's own GitHub release — the
  tablet compares the tag with its `versionName`, the window compares the number in its own
  `MobiXournal-<version>.msi` asset name, because the two shells number separately.
- **A card when one is newer**: the version on offer, the build you are on, a link to that release's own
  notes, and the two answers — **Remind me later** and **Update now**. The offer stays reachable from
  About after the card is dismissed.
- **Update now hands the package to the platform**, never installs it behind your back: the APK goes to
  Android's own installer through the app's private provider, the MSI to Windows' own installer.
- **On request, the version line itself is the button.** The tablet's build number in About is tappable
  and its subtitle is the state; the window's row does the same. "Already the latest" is announced at the
  bottom of the screen — a notification on Android, a pill over the page on Windows — so a tap always
  gets an answer.
- **Nothing is sent about you or your notebook**: the check is a GET of a public release page.

## 🖥️ MobiXournal Desktop v1.1.0

- **The update check, with the bottom pill** described above.
- **A packaged window that starts again.** The app image shipped without the `java.net.http` module, so
  the window died at startup while every test passed on a full JDK; the module is now part of the image.
- **Settings organised by what you are doing** — Workspace, Input, Drawing, Files — with flat groups,
  inline help and a remembered section, instead of one long page.
- **Reorder rows by dragging**, with the keyboard as an equal path: the tool strip's slots and the colour
  palette both move by grip, drag or arrow key, with the same glide.
- **Saves staged off the UI thread**, coalesced recovery checkpoints, bounded geometry caches and
  incremental `.xopp` parsing — the long jobs no longer compete with ink.

## 📱 MobiXournal v2.1.0 for Android

- **The update check, with the notification** described above.
- **Document work off the frame**: bundled audio discovery and waveform work, text and PDF search, PDF
  analysis and export I/O run on workers with captured state, so a page stays responsive while they run.
- **Saves that survive interruption**: full and incremental `.mobix` saves keep the manifest's creation
  time and unknown fields, **Save As** writes only after a successful write, and a cancelled Save As
  leaves the original untouched.
- **Per-tab image and audio assets stay per-tab** across switching and restart, and pruning protects every
  open tab.
- **Faster document paths**: a page-band index answers viewport and pointer questions without decoding,
  per-page searchable text is reused, and draft geometry is reused for append-only strokes.

## 🔐 Release engineering

- **Published tag builds are signed with one persistent certificate**, and fail closed without it: the
  preflight refuses to build, and an APK whose certificate does not match the configured fingerprint is
  deleted rather than published.
